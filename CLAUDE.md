# o-cs — the CS knowledge wiki (schema)

This repo is an LLM-maintained wiki of computer science knowledge, built by
reading the resources in `curriculum.md` and distilling them into interlinked
markdown pages. It is searched by [`oasis`](https://github.com/a1re1/oasis), a
hybrid BM25 + dense CLI search engine, so that coding agents (Claude, lci/GLM)
can pull specialized CS knowledge on demand.

Read `PROGRESS.md` first in every session: it says what is done, what is in
flight, and what is next.

## Layout

```
curriculum.md          # the seed manifest (sections 1.1 … 11.6); immutable
PROGRESS.md            # status per curriculum section + handoff notes
CLAUDE.md              # this schema
wiki/
  index.md             # GENERATED by scripts/build_index.py — never hand-edit
  log.md               # GENERATED from wiki/log/*.md — never hand-edit
  log/YYYY-MM-DD-<slug>.md   # one append-only entry per ingest/lint/query
  concepts/<slug>.md   # one page per concept, algorithm, data structure, theorem, system
  sources/<slug>.md    # one page per ingested course, textbook, or paper
  syntheses/<slug>.md  # cross-cutting insights, comparisons, "when to use X vs Y"
  paths/<slug>.md      # learning paths / prerequisite spines
scripts/               # fetch.py (URL -> text), build_index.py, lint.py
evals/                 # search-quality evals: queries.jsonl, run_eval.py, results/
skills/                # skills teaching lci/Claude how to use oasis on this corpus
reports/               # experiment log (learnings, charts, benchmark history)
raw/                   # gitignored fetch cache
```

## Page format

Every wiki page starts with YAML frontmatter:

```yaml
---
title: BM25
type: concept            # concept | source | synthesis | path
section: "10.3"          # curriculum section id (string)
level: 400               # 100..500
tags: [bm25, inverted-index, ranking]      # lower-kebab, from the section tag lists
sources: [manning-irb, robertson-bm25-1994] # slugs of wiki/sources pages
summary: One or two sentences that would make a good search snippet.
---
```

Slugs are lower-kebab-case ASCII (`dynamic-programming`, `raft`, `ostep`).
Link with Obsidian wikilinks `[[slug]]`; the slug is the filename without
`.md`, unique across all four directories.

### Concept page skeleton
```
# <Title>
**In one sentence.** …
## Why it matters
## How it works           (pseudocode / code welcome; never split fences)
## Complexity & trade-offs
## Pitfalls & gotchas
## Worked example
## Related               ([[links]] with one clause each on the relationship)
## Sources               (which pages/chapters this was distilled from)
```
Not every section is required; a short page with two sections beats padding.
Use the exact vocabulary a practitioner would type when searching ("amortized",
"two-phase locking", "write-ahead log") in headings — oasis boosts heading terms.

### Source page skeleton
```
# <Title> (<authors>, <year>)
frontmatter extras: authors, year, institution, url, license, format
## What it is             (course/text/paper; level; what it covers; how it is taught)
## Key ideas              (the 5–15 things worth knowing, each linking to a concept page)
## Chapter / lecture map  (for texts & courses)
## Notable claims & quotes
## What it adds           (beyond what the wiki already had; contradictions flagged)
```

## Workflows

**Ingest a resource** (one curriculum bullet, e.g. "OSTEP"):
1. Fetch with `scripts/fetch.py URL --max-chars N` (or `--grep`) into context; read
   critically. Prefer tables of contents + the chapters that carry the ideas.
2. Write/refresh the `wiki/sources/<slug>.md` page.
3. For each key idea: update the existing concept page if one exists (grep
   `wiki/concepts` for the slug and for synonyms first); otherwise create it.
   Flag contradictions with a `> **Contradiction:**` blockquote naming both sources.
4. Add cross-links both directions. Add the source slug to `sources:` of every
   concept page touched.
5. Write `wiki/log/<date>-ingest-<slug>.md` (3–10 lines: what was read, pages
   created/updated, open questions).
6. `scripts/build_index.py` (regenerates index.md, log.md; fails on broken
   wikilinks or missing frontmatter).
7. Tick the item in `PROGRESS.md`.

**Query**: search with `oasis --root wiki search "<query>" --json -k 8`, read the
hits, answer with citations. If the answer is a reusable synthesis, file it under
`wiki/syntheses/` and log it.

**Lint** (every ~10 ingests): run `scripts/lint.py` — orphans, broken links,
concepts mentioned ≥3 times without a page, stale claims, contradictions unresolved.

**Evals**: `evals/queries.jsonl` holds `{query, relevant: [slugs], section}` rows.
`evals/run_eval.py` runs oasis and reports recall@k, MRR, nDCG@3 per section.
Every corpus PR must not regress the eval; every oasis change must be measured
against it. Results are appended to `evals/results/history.jsonl` and summarized
in `reports/experiments.md`.

## Conventions

- Distill, don't copy. Paraphrase and compress; quote at most a sentence or two.
- Every page needs at least two inbound links after its ingest (index.md does not count).
- Prefer concrete: complexity bounds, invariants, exact algorithm steps, failure modes.
- Date everything in the log as `YYYY-MM-DD`.
- Commit per curriculum subsection; PRs merge into `main`.
- Delegate mechanical work (index rebuilds, link sweeps, harness code, tests)
  to lci with `--profile glm-5-3-flash`; never delegate the reading/distilling.
