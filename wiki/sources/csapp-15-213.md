# CSAPP / CMU 15-213 Introduction to Computer Systems

## What it is
Level 200; "the course that made me a programmer" for many. Chapters: 1 tour of a computer system;
2 representing and manipulating information (bits, integers, floats); 3 machine-level representation
of programs (x86-64: data movement, arithmetic, control, procedures, arrays, structs, buffer overflow);
4 processor architecture (Y86-64, pipelining); 5 optimizing program performance; 6 the memory
hierarchy (caches, locality); 7 linking; 8 exceptional control flow (exceptions, processes, signals,
nonlocal jumps); 9 virtual memory (address translation, page tables, memory mapping, dynamic memory
allocation, garbage collection, common memory bugs); 10 system-level I/O; 11 network programming;
12 concurrent programming. 15-213 Fall 2026 schedule follows this order with labs: cprogramminglab,
**datalab** (bit puzzles), **bomblab** (reverse-engineer assembly), **attacklab** (buffer overflow/ROP),
**cachelab**, **malloclab**, tshlab (shell), proxylab.

## Key ideas → pages
- Integers are finite: two's complement, overflow wraps, unsigned/signed conversion traps, shifts —
  [[integer-representation-and-bits]]; floats — [[floating-point]].
- The x86-64 stack discipline: frames, return addresses, callee/caller-saved registers, calling
  convention; why buffer overflows hijack control — [[calling-conventions-and-the-stack]],
  [[memory-safety-and-buffer-overflows]].
- Pointers are addresses; arrays decay to pointers; structs have alignment padding —
  [[pointers-and-memory]], [[memory-layout-stack-heap]].
- Linking: symbol resolution, relocation, static vs shared libraries, PIC — [[linking-and-loading]].
- Malloc design: implicit/explicit free lists, splitting/coalescing, fragmentation — [[dynamic-memory-allocation]].
- Memory hierarchy and cache-friendly code (ch. 6) — §4.1 [[caches-and-memory-hierarchy]]; virtual
  memory (ch. 9) — §4.2 [[virtual-memory]]; processes/signals (ch. 8) — §4.2 [[processes-and-threads]].

## Notable claims
- "Computer systems are not just hardware or software; they are a combination" — the perspective is
  always *what does this mean for my C program*.
- The three "great realities" of performance: constant factors matter, memory matters, and the
  processor executes your compiled code, not your source.

## What it adds
The grounding for §2.3 (C, pointers, memory) and §4.1–4.2; [[stanford-cs107]] covers the same first
half with more C practice; [[rust-book]] shows what a language that enforces these rules looks like.
