# xv6 and MIT 6.1810

## What it is
The xv6 book chapters mirror the kernel: 1 operating system interfaces (fork/exec/wait, file
descriptors and redirection, pipes, files); 2 organization (abstracting physical resources;
user/supervisor/machine modes; monolithic vs microkernel; the `proc` structure; `entry.S` →
`start` → `main`); 3 page tables (Sv39: 3-level, 4 KB pages, PTE flags; kernel page table
direct-mapped; `kalloc` free list; process address space with trampoline and trapframe;
`sbrk`, `exec` with ELF loading); 4 traps and system calls (`stvec`, `sepc`, `scause`; `uservec`/
`usertrap`/`usertrapret`; `syscall` dispatch; kernel-space traps; page-fault exceptions enabling
lazy allocation, copy-on-write fork, demand paging); 5 interrupts and device drivers (UART,
timer interrupts, concurrency in drivers); 6 locking (races, `acquire`/`release` spinlocks with
`amoswap`, lock ordering and deadlock, re-entrancy, locks and interrupts, memory ordering with
`__sync_synchronize`, sleep locks); 7 scheduling (`swtch` context switch, `scheduler`, `sleep`/
`wakeup` with the lost-wakeup problem, `wait`/`exit`/`kill`, real-world alternatives); 8 file
system (layers: disk, buffer cache, logging, inode, directory, pathname, file descriptor; the log
for crash recovery; block allocator; inode layout with 12 direct + 1 indirect; directories as
files; `namei`; `open`/`dup`/`pipe`). Labs: Xv6 and Unix utilities; system calls; page tables;
traps; copy-on-write fork; multithreading (uthread, `pthread` hash table); network driver (E1000);
locks (memory allocator, buffer cache); file system (large files, symlinks); mmap.
**CS162** (Berkeley): Pintos projects — threads/scheduler, user programs/syscalls, file system;
**CS140** (Stanford): Pintos; **CS6200** (Georgia Tech, free on Udacity): threads, PThreads,
scheduling, memory, I/O, virtualization, RPC, distributed file systems.
