# Large language models

**In one sentence.** Train a big decoder-only transformer to predict the next token on
most of the internet, and the compressed predictor becomes a general-purpose in-context
learner — then post-train it to follow instructions, serve it with a KV cache and clever
batching, ground it with retrieval and tools, and evaluate it with suspicion.

## Pretraining: objective and data (CS336 assignments 1 & 4; CS324; Brown et al. 2020)
Objective: maximize Σ log P(xₜ | x<ₜ) — cross-entropy per token — over a corpus, with the
causal transformer of [[transformers-and-attention]]; the loss is the same as an n-gram
model's ([[nlp-fundamentals]]) and its scaling is [[scaling-laws]]. **Data**: Common Crawl
(petabytes of HTML → text extraction → language ID → quality classifiers/heuristics
(Gopher rules, fastText trained on Wikipedia/books) → toxicity/PII filters → **deduplication**
(exact and MinHash near-dup — [[similarity-search-and-lsh]]; duplicates cause memorization
and waste compute) → **mixture weights** across web, code, books, papers, math, multilingual
(upsampling code improves reasoning; curriculum/annealing on high-quality data at the end);
15 T tokens for Llama 3; benchmark **decontamination**. Tokenizer: byte-level BPE with
100k–250k vocab. Training: AdamW, warmup + cosine/WSD, bf16, sequence length 4k–128k with
document masking, thousands of GPUs for weeks ([[neural-network-training]],
[[distributed-training-and-ml-systems]]); checkpoints and loss spikes are operational
concerns. The lineage: GPT-1 (2018, 117 M, pretrain + fine-tune), GPT-2 (2019, 1.5 B,
zero-shot task transfer, "too dangerous to release"), **GPT-3** (2020, 175 B, **in-context
learning**), Chinchilla, PaLM, GPT-4 (2023, multimodal, RLHF), Llama 1–3, Mistral/Mixtral,
Qwen, DeepSeek-V3/R1, Gemini, Claude. **nanoGPT** reproduces GPT-2 (124 M) on OpenWebText in
a day on 8 GPUs — the smallest complete recipe.

## Prompting and in-context learning (Brown et al. 2020; Wei et al. 2022)
A prompt is a conditioning prefix: **zero-shot** (instruction only), **few-shot** (k
input–output examples — the model infers the task; order and format matter; ICL behaves
like implicit Bayesian inference/gradient descent on the examples), **chain-of-thought**
("let's think step by step" or worked examples — decomposes multi-step reasoning into
tokens the model can condition on; only helps at scale), self-consistency (sample many
chains, majority vote), ReAct (interleave reasoning and tool calls), **system prompts**
(persona, rules, tool definitions), structured output (JSON schemas, constrained decoding).
Prompt engineering is real but brittle (sensitivity to wording, position — "lost in the
middle" for long contexts); much of it is being absorbed into post-training and reasoning
models ([[llm-post-training-sft-rlhf-dpo]]). Context windows (4k → 128k → 1M+) let whole
documents and codebases be prompts; effective use degrades before the limit
([[efficient-transformers-and-long-context]]).

## Decoding
Greedy (repetitive), **beam search** (for translation, not open-ended text — bland/looping),
**sampling** with **temperature** τ (logits/τ; τ → 0 greedy, τ > 1 flatter), **top-k**, **top-p /
nucleus** (smallest set with cumulative probability ≥ p — Holtzman 2020: pure sampling from
the tail produces incoherence, truncation fixes it), repetition/frequency penalties,
min-p; stop sequences; logit bias; **constrained decoding** with grammars for valid
JSON/code. Latency: per-token decode is memory-bound (read all weights + KV cache per
token — [[roofline-model]]); prefill is compute-bound.

## Serving and inference optimization ([[llm-inference-and-serving]] in depth)
**KV cache** (per token: 2 × layers × d × bytes; 70 B model at 128k context ≈ tens of GB) —
paged (vLLM's PagedAttention — virtual memory for the cache, [[virtual-memory]]),
prefix caching for shared prompts, multi-/grouped-query attention to shrink it;
**continuous batching** (admit new requests between decode steps) for throughput;
**quantization** (weights to INT8/INT4/FP8 — GPTQ, AWQ, bitsandbytes; KV to 8-bit; ~2–4×
memory reduction with small quality loss); **speculative decoding** (a small draft model
proposes k tokens, the big model verifies in one forward pass — exact distribution,
2–3× speedup); **distillation** to smaller students; FlashAttention/FlashDecoding kernels;
tensor parallel across GPUs for the largest models; **MoE** (Mixtral 8×7B, DeepSeek-V3
671 B/37 B active) routes tokens to experts — more capacity per FLOP, memory-heavy;
metrics: time-to-first-token, tokens/s, cost per million tokens. Edge: llama.cpp with
4-bit weights on a laptop.

## Retrieval, tools, and agents — how do I make an LLM answer questions about my own documents? (RAG)
**RAG** (Lewis et al. 2020): embed a query, retrieve top-k chunks from a vector index
([[dense-retrieval-and-embeddings]], hybrid with BM25 — [[bm25]]; this wiki + oasis is an
instance), stuff them into the prompt, cite; reduces hallucination and lets knowledge be
updated without retraining; failure modes: retrieval misses, lost-in-the-middle, chunking,
and the model ignoring or over-trusting context; evaluation of retrieval and generation
separately ([[evaluation-of-ir-systems]]). **Tool use / function calling**: the model emits a
structured call (search, calculator, code interpreter, database, browser), the runtime
executes and returns results — grounding, arithmetic, up-to-date data; protocols (MCP)
standardize tool schemas. **Agents**: loop {plan → act (tool) → observe} with memory
(scratchpads, retrieval) and stopping rules — coding agents, browser agents, research
agents; reliability compounds per step (0.95¹⁰ ≈ 0.6), so verification, sandboxing, and
narrow tools matter ([[llm-agents-and-tool-use]]); **prompt injection** via tool outputs is
the security problem ([[ai-safety-and-alignment]], [[web-security]]).

## Multimodal and the model landscape
Vision-language: image encoder (ViT/CLIP) → projector → LLM (LLaVA, GPT-4V, Gemini);
native multimodal pretraining; audio (Whisper for ASR; speech-to-speech); video; image
generation attached via diffusion ([[deep-generative-models]]). **Open weights** (Llama 3,
Mistral, Qwen, Gemma, DeepSeek) vs closed APIs (GPT, Claude, Gemini): open models enable
fine-tuning, local deployment, and research; closed lead on frontier capability by months;
licensing ≠ open source (data and code often withheld). Small language models (1–8 B)
distilled from large ones cover most narrow tasks.

## Evaluation and failure modes ([[llm-evaluation-and-benchmarks]])
Benchmarks: MMLU (knowledge), GSM8K/MATH (math), HumanEval/SWE-bench (code), GPQA, MMMU
(multimodal), long-context needles, arena Elo (human preference), and task-specific
evals; problems — **contamination** (test sets in the pretraining data), saturation, metric
gaming, prompt sensitivity, and preference judges' bias toward verbosity. Failure modes:
**hallucination** (fluent falsehoods; calibration and RAG/tools mitigate; models are better
at knowing what they know than they act), **sycophancy** (agreeing with the user — an RLHF
side effect), **memorization** and PII leakage, brittleness to paraphrase, arithmetic/spelling
via tokenization, jailbreaks and prompt injection, bias and toxicity from data
([[fairness-in-machine-learning]]). Interpretability (probing, circuits, sparse
autoencoders — SLP3's new chapter; [[interpretability-and-explainability]]) is how the field
tries to see inside.

## Pitfalls
- Confusing a base model with a chat model (prompt formats, system prompts, stop tokens).
- Benchmarks without decontamination; single-prompt comparisons.
- Greedy decoding for creative tasks; temperature 1 with no truncation.
- Ignoring the KV cache and batch size in cost estimates; serving at batch 1.
- RAG with bad chunking/retrieval and blaming the model.
- Trusting tool outputs (prompt injection) or the model's own confidence.
