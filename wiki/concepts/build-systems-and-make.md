# Build systems and Make

**In one sentence.** Declare what depends on what and how to make each thing; the tool performs a
topological sort ([[dags-and-partial-orders]]) and redoes only what changed.

## Make (GNU Make manual)
```make
CC := cc
CFLAGS := -O2 -Wall
objs := $(patsubst %.c,%.o,$(wildcard *.c))
app: $(objs)            # target: prerequisites
	$(CC) -o $@ $^      # recipe (TAB-indented); $@ target, $^ all prereqs, $< first prereq
%.o: %.c                # pattern rule
	$(CC) $(CFLAGS) -c $< -o $@
.PHONY: clean test      # targets that are not files
clean: ; rm -f app $(objs)
```
- Rebuild rule: a target is out of date if it does not exist or any prerequisite's mtime is newer;
  recursion through the graph; `make -j8` runs independent recipes in parallel.
- `:=` (expand now) vs `=` (expand on use); functions (`wildcard`, `patsubst`, `shell`);
  header dependencies via `-MMD` generated `.d` files; `include`. Avoid recursive make (breaks the
  global DAG); keep rules hermetic (only declared inputs).
- Make is also a fine task runner for any project (`make test lint docs`).

## Beyond Make
| System | Change detection | Notable |
|---|---|---|
| Ninja | mtimes, fast | generated by CMake/Meson/gn |
| CMake / Meson | generators for C/C++ | portability, find_package |
| Bazel / Buck / Pants | content hashes, sandboxed hermetic actions, remote cache/execution | monorepos, reproducibility |
| Cargo / Go / Gradle / Maven / npm scripts | language-integrated | build + dependency management in one |
| Nix / Guix | hash of all inputs incl. toolchain | fully reproducible environments |
Key ideas: hermeticity (outputs depend only on declared inputs), reproducibility (same inputs →
bit-identical outputs), caching keyed by input hashes, and the build graph as data.

## Dependency management (Missing Semester lecture 8)
- Packages published to repositories (PyPI, crates.io, npm, apt) with **semantic versions**
  `MAJOR.MINOR.PATCH` — breaking / compatible additions / fixes; constraints like `^1.4` mean "any
  1.x ≥ 1.4".
- The resolver picks concrete versions satisfying all constraints and records them in a **lock
  file** (`Cargo.lock`, `package-lock.json`, `uv.lock`) so every machine builds the same graph;
  update deliberately. Diamond dependencies and single-version policies; vendoring for isolation.
- Supply-chain hygiene: pin, verify hashes, audit advisories ([[security-principles]]).
- **Continuous integration**: on every push run build + tests + lint in a clean environment;
  the test pyramid and terminology (unit/integration/regression/mocking — [[unit-testing]]).

## Pitfalls
- Tabs vs spaces in Makefiles; missing `.PHONY` so a file named `test` blocks the target.
- Undeclared dependencies (works locally, fails in CI); timestamps confused by clock skew or `git
  checkout` (hash-based systems fix this).
- Non-reproducible builds (timestamps embedded, unpinned toolchains).
