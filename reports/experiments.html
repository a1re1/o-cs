Plan

The wiki follows Karpathy's LLM-wiki pattern: sources are read once, distilled into concept, source, synthesis and path pages with frontmatter and wikilinks, and an index is regenerated by script. Search quality is measured after every ingest rather than assumed.

  • Scaffold: schema (CLAUDE.md), progress tracker, index builder, fetch tool
  • Ingest §1 Foundations → §11 Specialized, in curriculum order
  • Eval harness: recall@k, MRR, nDCG@3 per curriculum section, history file, regression gate
  • Skill for lci/Claude: how to query oasis and drill into hits
  • LLM eval: lci answers CS questions using oasis; grade tool use and answers
  • oasis improvements measured against the eval (frontmatter-aware chunks, path filter, weights, MCP serve)

2026-09-01 20:05 setup

Read the oasis source: heading-aware chunker (256 whitespace tokens, 32 overlap, never splits fences), BM25 with identifier-aware tokenizer and 2× heading boost, bge-small-en-v1.5 dense index with a blake3 embedding cache, reciprocal rank fusion (k=60) plus a 0.02 exact-phrase bonus. Early hypotheses to test: (1) YAML frontmatter becomes a headingless chunk and its title/tags never reach the other chunks of the page, so a tag-only query cannot find a page's body; (2) RRF with equal weights will over-reward dense hits on short pages; (3) 256-token chunks are small for pages with long code blocks.
