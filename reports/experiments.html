Plan

The wiki follows Karpathy's LLM-wiki pattern: sources are read once, distilled into concept, source, synthesis and path pages with frontmatter and wikilinks, and an index is regenerated by script. Search quality is measured after every ingest rather than assumed; a regression gate fails the run if recall@3 drops by more than 0.02.

  • Scaffold: schema (CLAUDE.md), progress tracker, index builder, fetch tool
  • Eval harness: recall@k, MRR, nDCG@3 per curriculum section, history file, regression gate (built by lci / GLM-5.3 Flash, PR #1)
  • §1 Foundations (7), §2 Programming (6), §3 Algorithms (4) ingested; §4 Systems in progress (4.1, 4.2 done)
  • §4.3 Compilers → §11 Specialized, in curriculum order
  • oasis PR #2 merged: per-page collapse and --ignore globs, measured against the eval
  • oasis next: frontmatter-aware chunk text, path filter, serve/batch mode (no per-query index rebuild), weights tuned on the paraphrase subset
  • Skill for lci/Claude: how to query oasis and drill into hits
  • LLM eval: lci answers CS questions using oasis; grade tool use and answers

Findings

1. Skipping the generated index page and collapsing hits per document help modestly; a harness bug briefly made them look dramatic.

Oasis ranks chunks, not pages. On the first 129 queries a second chunk of an already-listed page appeared in the top 3 for 92 queries, and the auto-generated index.md (every title and summary in one file) appeared in the top 3 for 41. Both fixes shipped in oasis PR #2 (--ignore <glob>, --per-page N defaulting to one hit per document), implemented by lci from a definition-of-done contract. Measured on the same 193 queries after the fix:

fail The first version of this finding claimed recall@1 0.891 → 0.922 and MRR 0.935 → 0.957 from a harness simulation. That simulation relabelled the run mode to lexical+dedupe before the query loop, and the code that appends --lexical-only tested for the exact string lexical, so every "dedupe" run silently used hybrid search. The "gain" was hybrid versus lexical. Caught because a direct CLI call could not reproduce the ranking the harness recorded; two identical harness runs then differed in zero queries, which ruled out nondeterminism and pointed back at the harness. A pool-widening change to oasis justified by the bad number was reverted before merge. Lesson recorded in the harness: the mode label and the mode flag are now separate arguments, and every experimental run prints the exact oasis command line.

At 193 queries / 200 pages (finding 1 table) hybrid leads lexical by 0.021 recall@3 and 0.014 MRR. The only query lexical cannot place in its top 10 at all is a paraphrase with no shared vocabulary ("keep track of which items are in the same group as connections are added" → union-find); hybrid ranks it 7th. * nearest lexical run (84 queries, 104 pages). Each oasis invocation rebuilds the index, so a hybrid query costs about 4 s against 0.5 s lexical on this corpus; the eval loop therefore runs lexical after every ingest and hybrid at checkpoints. A serve/batch mode in oasis would remove the rebuild cost and make hybrid the default again.

3. Search quality holds as the corpus triples; the dips are per-section, not global.

Per-section recall@3 is 1.0 for eleven of thirteen sections. The two weak sections are §2.1 intro programming (0.917: two "which course" queries land on sibling course pages) and §2.6 developer tooling (0.800, rising to 0.900 with dedupe: task-phrased queries like "trace which system calls a program makes" match reference-style pages weakly, and the index page outranks them).

4. The eval is too easy in one way and honest in another.

About half the queries share vocabulary with their target's title or tags, which BM25 with heading boost answers trivially. The harder rows are the paraphrase and question kinds ("why does signed integer overflow let the compiler delete my check"), and those are where hybrid earns its cost. Next step is a held-out adversarial set written without looking at the pages, plus nDCG that credits multiple relevant pages.

5. Process findings (failures included).
  • fail Writing pages with cd wiki && cat > … chains silently skipped the first file of two batches because the shell cwd persisted between calls; two concept pages were missing until the index reported orphaned links. Fix: absolute paths everywhere; the index builder now counts "wanted" pages.
  • fail A section-filtered eval run (--section 2.6) was appended to the history file and would have become the regression baseline. Removed by hand; section runs now use --no-history.
  • fail Text extraction: MIT's Mathematics for CS PDF came out with control characters that made grep treat it as binary; page markers were inconsistent, so a page-range slicer was abandoned in favour of regex slicing on section titles. Two mirrors of Parnas 1972 returned 403 before a third worked.
  • ok Delegation: lci with GLM-5.3 Flash built the eval harness (metrics, fixtures, unit tests, README) in one run plus a narrow --continue to finish the last two items after exhausting its iteration budget. The definition-of-done contract mattered more than the prompt length.
  • ok Reading before writing pays: cross-section links appeared only because the same reader wrote both ends (fold = structural induction's twin; Okasaki's "multiple futures" = why amortized bounds assume linear use; Wadler's effect-in-the-type = Rust's Result/?; Parnas, GoF, Fowler and Liskov as four statements of "isolate the axis of change").
